# 内置能力说明（Pawch 自己的插件与开关）

## 什么时候读这份

- 用户问「断线取消 / 中枢 / 记忆库 / css-ui / 功能桥接 / 用量价格 / 项目文件 / 时间线 / 浏览器 / 插件制作器 是干嘛的」。
- 用户问「某个开关在哪」「打开会发生什么」「我明明开着为什么没效果」。
- 任何关于**本应用自身功能**的问题——先读这里，再去读代码或配置。

## 先分清两种开关（2026-11-01 用户实锤的坑）

1. **插件行开关**（设置 → 插件，每行右侧那个）：决定插件是否加载、界面入口出不出现。存的是 `settings.disabled_plugins`。
2. **功能开关**（`settings.features.<键>`）：manifest 声明了 `feature` 的插件，行开关**同时**写这里——设计上「一个能力只留一个开关」。

坑：**从没被手动切过的插件**，`features` 里还是默认值，和行开关显示的状态可能不一致。
例：`断线取消` 默认 `false`，但插件行开关是亮的（因为不在停用名单里）。
所以回答「现在到底开没开」之前，**必须 `settings action=get` 看 `features` 的真实值**，不要只看插件行。

## 断线取消的准确语义（最常被问）

- **做**：本轮任务的 SSE 连接断了（刷新、关标签、网络掉线）→ 立刻取消这轮 agent 任务，不再继续调模型烧 token。
- **不做**：不保存/恢复对话，不管断线重连，不影响已经落盘的内容。
- 关着（默认）时：任务继续在后台跑完，刷新页面回来能接着看结果。

## 查状态的标准动作

1. `settings action=get` → 看 `features`（真实开关）与 `disabled_plugins`（停用名单）。
2. `auto method=list_panels` → 看面板类插件的启用态。
3. 要改：`settings action=set patch={"features.<键>": true/false}`，或让用户去 设置→插件 点那一行。

## 别做的事（这轮踩过的）

- **别去 `C:\Users\...\AppData`、别的软件（ZCode/Electron）安装目录、`~/.zcode` 里搜关键词**——那些是别的程序的文件，和本应用无关。用户问自己的能力，答案在本仓库的 `plugins/`、`src/`、`settings.json` 里。
- **别为了「看清楚」去改用户的开关**。要确认状态就 `settings action=get`；写操作只在用户明确要求时做。
- 别把「插件启用」当成「功能生效」——见上面两种开关。
